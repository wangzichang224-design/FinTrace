# FinTrace 路线图：从费控审核到通用财务助手

## 一、近期：Showcase 打样

目标不是继续堆功能，而是做出一个能被面试官和潜在用户快速看懂的 1-2 分钟 Demo。

近期重点：

- 用 `datasets/showcase_fintrace_v1` 展示三类复杂风险：时空冲突、拆单规避、事由与附件不一致。
- 前端默认站在财务人员视角，只展示批次概览、风险案件、原因和建议动作。
- 诊断与优化台展示字段溯源、规则链、本体上下文、推理摘要和 LLM 门控。
- 对外表述为“冻结样本集回归通过”，不夸大为真实企业泛化能力。

Showcase 叙事：

1. 财务人员面对 ERP 导出、OCR 文本、审批聊天和附件清单。
2. FinTrace 批量归并案件并识别高风险 case。
3. 点击 case 后可以看到证据来自哪里、规则为什么命中、系统为什么转人工复核。
4. 人工复核通过后可以沉淀为受控例外记忆，但不会覆盖缺原件、重复发票、黑名单等底线风险。

## 二、中期：审计思维深化

报销审核跑通后，FinTrace 需要从形式审查走向实质性测试。

中期方向：

- 三单匹配：发票、采购订单、入库/验收单自动交叉比对。
- 合同 RAG：读取采购合同、客户协议和付款条款，核验金额、日期、供应商和交付物。
- 预算与战略对标：对部门、区域、项目维度做费用趋势分析，识别“费用上升但业务产出未同步提升”的异常。
- 独立评测：引入财务/审计人员标注的小规模真实脱敏样本，避免只依赖自生成红队数据。

产品边界：

- FinTrace 不替代 ERP 的付款、凭证、权限和主数据系统。
- FinTrace 是 ERP 之上的智能风控与审计解释层，负责风险筛查、证据组织、人工复核建议和评测闭环。

## 三、长期：通用财务助手

长期目标是从单点费控 Agent 演进为财务中台的智能入口。

长期模块：

- Compliance Agent：阅读合同、外文协议和供应商材料，提取付款节点、违约条款和合规红线。
- FP&A Agent：基于历史支出、预算口径和外部经济指标生成滚动预算草案。
- Conversational BI：业务主管用自然语言查询区域、项目、客户和费用结构，系统返回可追溯结论和图表。

上线前必须补齐：

- 真实 ERP/HR/CRM/供应商系统的数据接口和字段契约。
- 生产级 OCR、人工纠错和附件证据留痕。
- 多用户权限、审批流、数据库、不可篡改审计日志。
- 规则版本管理、灰度发布、回滚和影响评估。
- 数据脱敏、密钥管理、访问控制和模型供应商合规评估。
- 基于真实脱敏样本的 UAT、Precision/Recall/F1 和财务人员节省时长验证。
