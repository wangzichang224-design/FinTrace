# FinTrace MVP 范围说明

## 一句话定位

FinTrace v0.1 是一个面向企业财务/共享中心的“批量报销风险初筛与溯源调试工具”，先解决 CSV/XLSX 批量导入后的可解释审查问题，而不是一开始就替代 ERP 或财务终审。

## 目标用户

- 财务共享中心审核员：每天面对几十到几百笔报销，需要先筛出缺原件、重复票、超标准和需要复核的案件。
- 财务内控/审计人员：需要看到字段来源、规则命中、阈值计算和错误归因，方便复核与抽查。
- AI 产品/解决方案面试场景：需要展示从业务痛点、MVP、规则边界、评测和前端解释的完整闭环。

## 首批痛点

- ERP 批量导出后，人工逐行看金额、发票号和附件，低价值重复劳动多。
- 规则命中不可解释，出错后很难定位是字段抽取、规则阈值、上下文还是模型推理问题。
- 企业不敢让 LLM 直接决定财务结果，但希望 LLM 帮忙生成结构化审计底稿。

## v0.1 MVP 必须有

- CSV/XLSX 批量导入，支持本地目录路径。
- 案件归并：一行 ERP 对应一个 case，并关联同名/同报销单附件文本。
- 字段级溯源：金额、员工、费用类型、发票号、供应商等关键字段保留来源。
- 本地稳定模型：不依赖外部 LLM，输出确定性结论。
- 阻断控制与上下文风险信号分层：阻断控制可直达拒绝/反舞弊，上下文风险进入人工复核或柔性判断。
- JSON/JSONL 结果导出：每个 batch 和 case 都能离线复查。

## v0.2 展示与增强能力

- Streamlit 中文控制台：服务录屏、图文展示和面试讲解。
- DeepSeek 结构化审计底稿：只作为增强层，必须通过本地基准和合规门控。
- 红蓝评测台：用于验证规则边界、字段抽取和误杀/漏放。
- 高仿真 mock 数据：用于作品集展示，不替代真实企业数据接入。

## 明确不做

- v0.1 不直接写回真实 ERP。
- v0.1 不承诺端到端自动审批。
- v0.1 不把 LLM 作为最终财务裁判。
- v0.1 不依赖真实 CRM/HR/供应商系统；真实接入方案见 `ONTOLOGY_COLD_START.md`。

## 第一批用户假设

第一批用户不是 CFO，而是“需要先把批量材料看出风险层级的财务审核员/内控同学”。他们最痛的是批量低效和错误难定位，因此 MVP 的价值是“先筛出来、讲清楚、能复核”，而不是“全自动放款”。
